## 4. Notefile inventory — device emits vs ingest consumes
Firmware explicit app notefiles (SongbirdConfig.h:159-163):
  track.qo (port10), alert.qo (port11), command_ack.qo (port12), health.qo, command.qi (inbound)
Firmware ALSO relies on Notecard-generated system notefiles:
  _track.qo (GPS, auto), _log.qo (Mojo power), _health.qo (voltage alerts), _geolocate.qo,
  _session.qo  (see SongbirdTasks.cpp:773-774 and SongbirdNotecard.cpp:732,939)
Ingest handles: track.qo, _track.qo, _log.qo, _health.qo, _geolocate.qo, alert.qo,
  command_ack.qo, _session.qo (api-ingest/index.ts:195-263 + index.test.ts:5-6)
CONFIRMED CONTRACT GAP (High): firmware defines AND actively writes app-level health.qo
  (NOTEFILE_HEALTH, SongbirdConfig.h:163) via notecardSendHealthNote() at
  SongbirdNotecard.cpp:513/547 — called for periodic health (SongbirdTasks.cpp:159) AND
  the brownout/shutdown note (SongbirdTasks.cpp:1031). BUT the ingest Lambda only branches
  on system _health.qo (api-ingest/index.ts:210), never app-level health.qo. Result:
  firmware-emitted health.qo events (including the PVD/brownout shutdown note carrying
  reason+voltage) are received by ingest but fall through with NO handler -> silently
  dropped from the pipeline. The shutdown note in particular goes nowhere. This is a real
  end-to-end integration bug, not dead code. -> Cross-component section, High severity.
  (Firmware concurrency itself looks well-structured: g_i2cMutex/g_configMutex/g_stateMutex,
   audio/note/config queues, volatile ISR flags incl. g_pvdShutdownRequested — leave detailed
   firmware verdict to the firmware subagent.)
